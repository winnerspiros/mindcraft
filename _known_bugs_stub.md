## Per-server portability (home OP vs guest survival)
- servers.json in the bot root is the only per-server config. Selection: UWU_SERVER env wins, else file `active`, else `home`; missing file = home defaults so live behavior never changes by accident. New servers start as a copy of the `guest` block (op false, rcon disabled, easyauth false, version auto, seed null). Configurable per server: connection (host/port/auth/version), op, easyauth, auto_auth + auth_password, kit_probe, personality (yandere|normal), teleports {enabled, probe, send, accept, deny, autoaccept, auto_accept: trusted|beloved|off}, combat {fight_back, retaliate, warn_hits, no_console_punish}, modes overrides, rcon, seed.
- standalone.js must call serverContext() AFTER setSettings() and BEFORE the agent connects: it rewrites settings.host/port/auth/minecraft_version and logs the `[server] context=` line. Any helper reading settings before that call sees stale home values.
- op=false means survival-only everywhere, with honest fallbacks, never silent skips: pin cheat mode off at init AND refuse setOn(cheat,true); refuse every power: command at the command-layer gate; guard every direct /give /summon /kill /data /tp chat send and every RCON call with canOp()/rconConfig() so foreign servers see zero OP traffic; skip spawn _gearUp and respawn re-kit (equip-what-she-has only); suffocation escape keeps resistance + walk-out, no RCON tp.
- Personality is a prompt overlay, not a second profile: promptConvo appends personalityOverlay() AFTER profile.conversing so it wins ties; yandere returns ''. Normal = the real-player easter-egg drop (Elena talking directly, no ~nya/pet names/possessiveness, no beloved/BELOVED, no jealous violence, console never punishment, melee/bow-only real self-defense, stop when they stop). Overlay alone is insufficient — every code path that reads profile.beloved, rank beloved, or isBelovedName (login-greet approach, sleep_together odds, comeHere no-debate, TP willingness) must also gate on personality(), or normal still clings through mechanics while the voice claims otherwise.
- Teleports off-home are consensual TPA, never OP: !tpa / !tpaccept / !tpdeny carry no power: gate (both sides consent via the plugin). Nothing tp-related is said OR sent until capability is proven: gate on isTeleportsAvailable() (home true by config, guest false until the tab-complete /tprequest probe confirms — unknown = no tp talk, never unknown-command noise). !tpa is last-resort + walking-is-better (real reason walking cannot do, one pending request per player per 5min, second call refused not re-sent); walk-failure and comeHere lines never advertise tp ("send coords, I'll walk over") — tp commands are hers to RECEIVE when players ask, not to offer. Incoming-request watcher auto-accepts per auto_accept (trusted = rank friend+, beloved = beloved only, off = everything to the brain); strangers never auto-accept into home/base. Arm the watcher on EVERY context — never nest it inside a guest-only join flow behind an early return, or home silently never listens while guest works. Live command names verified via RCON help (tprequest, tpaccept/tpdeny take optional name; tpautoaccept list|add|remove|clear; bare /tpa is NOT a server command here — the !tpa brain command sends the configured send string).
- Combat on every personality: no_console_punish is NOT configurable (always true — never /effect /kick /summon/TNT/crystals as punishment). Modes self_defense/cowardice/retaliation stay ON in both personas; normal only changes the voice around them, never disarms them.

- Auth: home keeps easyauth /login on the login event only. ## LightAnticheat false-positive tuning (fail-open, never wedge)
- Triage shape before tuning: correlate LAC lines with `standing on air - force-sending blocks below`, login lines (Java direct vs Geyser UDP), and setback targets. Same setback coords repeating = standing-still FP on ghost ground; travel across coords with sprint bursts = jump/sprint FP. Tune the shape, never a single line.
- Fly hover gate order, all required: window is 60 ticks (3s, not 20t) and a flag needs TWO consecutive suspicious windows (flyConfirm counter; grounded/jump-rise resets it) — a single 1s stall-then-replay reads as hover, a real fly hack re-triggers in 3s while a faller lands. Gates: (1) exempt states first — creative/spectator, isFallFlying, isPassenger, onClimbable, isInWater, isInLava, slow-descent block, LEVITATION/SLOW_FALLING/JUMP_BOOST effects, launched (hurtTime or deltaMovement.y above jump velocity); (2) server grounded = onGround OR verticalCollisionBelow (client flag alone flickers during sprint-jumps on laggy ticks); (3) stillness = XZ moved <0.3 since window opened and net fall <1.0 means standing, reset no flag; (4) ground proximity = solid collision-shape block within 2 below (loaded-only) means ghost ground, reset no flag; (5) jump-arc rise = window max Y minus window start Y above ~0.35 means real jumping (hover hacks never gain height), reset no flag. Flag + setback only when all gates fail; log discriminator values (fall, rise) in the detail string so the next tune uses real data.
- Phase login grace: a just-joined player materializes where the server puts them (login/bed point inside terrain after world edits reads as inside-solid for seconds with standing-on-air desync + tick lag) — that is spawn overlap, not a phase hack. Track first-seen wall clock per UUID (JOIN_MS) and skip the phase check for 60s after first movement packet; real phase hacks run for minutes, so the blind window costs nothing. Keep every other check enforcing from tick one.
- All block reads on the movement path must be loaded-only via getChunkNow and fail-open on null chunk — never block on chunk/world futures on the Netty IO thread (IO-thread block + server-thread channel wait = silent wedge with RCON still answering).
- BadPacketsF sprint rule: vanilla clients re-send START_SPRINTING about 1/sec while sprinting AND stall replays dump same-edges in bursts, so ANY same-edge count threshold false-positives eventually — count TRANSITIONS (START->STOP or STOP->START) instead. Same-edge storms = 0 transitions = never flags by construction. Window is 5s with a 24-transition bar (a toggle exploit sustains 10-20/sec = 50-100/5s; a login stall-replay dumps one burst and stops — a 2s/10 bar false-flagged a real player on fresh login). One flag per burst (clear histogram), LOG-ONLY never setback. Botcraft InputsToSprint plausibility annex: resolve every START edge against spectator/passenger/fall-flying/crouch/blindness/surface-swim/food<=6/silent-client (no movement packet in >1.5s) and record the verdict for the detail string — implausible edges never flag alone and never OPEN a new burst (they join the old window). STOP edges are always plausible.
- Java source stays ASCII-only: non-ASCII comment characters break the javac build; MobEffects jump constant is JUMP_BOOST.
- Deploy: build in lightanticheat-src via ./build.sh, verify the new detail string ships in the jar (strings check), RCON save-all, install versioned jar name, archive the old jar to ~/mods-hold, restart minecraft-fabric.service, verify Loaded + Done + zero new flags.
